# Analysis: Repetitive Sequences from ProteinMPNN

## Problem Summary

The sequences generated by ProteinMPNN show **excessive repetition** of amino acids, particularly:
- **Glycine (G)**: Long runs of GGGGGG...
- **Histidine (H)**: Long runs of HHHHH...
- **Alanine (A)**, **Lysine (K)**, **Leucine (L)**, **Glutamate (E)**: Frequent repetition

### Example Sequences
```
>sample_0000, T=0.1, sample=1
HEHHEHGHHHHHHHHHHHGHHHHHLQQLHHHHHHHHHHHHHHHHLHHHHH

>sample_0005, T=0.1, sample=1
GSGGAAGAGAGAGAGGGADAAGAAAGAAGAGAGAGAGGGGAGGAGAGGAA

>sample_0001, T=0.1, sample=2
HHHHHHHHHIAHHHHHHHHHHHHHHKHHHHHHHHHHHHHHHHHHHHHHHH
```

These patterns are **NOT realistic** for natural proteins, which typically have diverse amino acid compositions.

---

## Root Causes Identified

### 1. **LOW SAMPLING TEMPERATURE (0.1)** ⚠️ CRITICAL

**Location:** `run_proteinmpnn.sh` line 15
```bash
TEMPERATURE=0.1
```

**Problem:**
- Temperature 0.1 is **extremely conservative**
- ProteinMPNN becomes overly confident and picks the same amino acids repeatedly
- This is the **PRIMARY cause** of repetitive sequences

**Solution:**
- Increase temperature to **0.3-0.5** for more diversity
- Temperature 0.3 is a good balance between stability and diversity
- Temperature 0.5-1.0 for maximum diversity (but may reduce stability)

**Fix:**
```bash
TEMPERATURE=0.3  # Changed from 0.1
```

---

### 2. **POOR BACKBONE QUALITY** ⚠️ MAJOR ISSUE

**Problem:**
The generated backbones may have structural issues that make ProteinMPNN struggle:

#### a) **Training Configuration Issues**

**Location:** `train_and_evaluate_enhanced_flow.sh` line 13
```bash
EPOCHS=5  # Too few!
```

**Problem:**
- Only 5 epochs is **insufficient** for convergence
- Flow matching models typically need 50-100 epochs
- Undertrained models produce poor quality backbones

**Solution:**
```bash
EPOCHS=100  # Increased from 5
```

#### b) **Learning Rate Too High**

**Location:** `train_and_evaluate_enhanced_flow.sh` line 15
```bash
LR=1e-4  # Too high for stable training
```

**Problem:**
- Learning rate 1e-4 may cause instability
- Can lead to poor convergence and noisy predictions

**Solution:**
```bash
LR=5e-5  # Reduced from 1e-4 for stability
```

#### c) **Insufficient Sampling Steps**

**Location:** `train_and_evaluate_enhanced_flow.sh` line 26
```bash
NUM_STEPS=50  # May be too few
```

**Problem:**
- 50 steps may not be enough for high-quality structures
- Flow matching benefits from more steps for complex structures

**Solution:**
```bash
NUM_STEPS=100  # Increased from 50 for better quality
```

---

### 3. **TIME SAMPLING BIAS IN TRAINING** ⚠️ MODERATE ISSUE

**Location:** `foldingdiff/flow_models.py` lines 165-172
```python
# Sample time with bias towards easier timesteps early in training
if self.train_epoch_counter < self.epochs * 0.2:
    # Early training: focus on t near 0 (easier)
    t = torch.rand(batch_size, device=device) * 0.5
else:
    # Later training: uniform sampling
    t = self.flow_schedule.sample_time(batch_size, device)
```

**Problem:**
- With only 5 epochs, the model spends **1 epoch** (20%) on easy timesteps
- This is **too short** for proper warm-up
- The model doesn't learn the full time range properly

**Solution:**
Either increase epochs to 100 (then 20 epochs warm-up is reasonable), or adjust the warm-up ratio:
```python
if self.train_epoch_counter < self.epochs * 0.3:  # 30% warm-up
    t = torch.rand(batch_size, device=device) * 0.5
```

---

### 4. **ANGULAR FEATURE WRAPPING** ⚠️ MINOR ISSUE

**Location:** `sample_from_checkpoint.py` lines 95-98
```python
# Add means back to angles
sample_corrected = sample.clone()
sample_corrected[:, 2] += np.pi  # omega: add 180°
sample_corrected[:, 3] += 1.92   # tau: add ~110°
```

**Problem:**
- Manual offset addition may not match training normalization
- Could lead to slightly incorrect backbone geometry
- ProteinMPNN is sensitive to backbone quality

**Solution:**
Ensure the angle denormalization matches the training normalization exactly. Check if the dataset uses the same offsets.

---

### 5. **NO DIVERSITY MECHANISMS** ⚠️ MODERATE ISSUE

**Location:** `bin/design_sequences_mpnn.py`

**Problem:**
- No nucleus sampling (top-p)
- No top-k filtering
- Only temperature control
- ProteinMPNN supports these but they're not used

**Solution:**
Add diversity parameters to ProteinMPNN call:
```python
cmd = [
    "python", str(mpnn_script),
    "--ca_only",
    "--pdb_path", str(pdb_path.absolute()),
    "--out_folder", str(output_dir.absolute()),
    "--num_seq_per_target", str(num_sequences),
    "--sampling_temp", str(temperature),
    "--seed", "42",
    "--batch_size", "1",
    # ADD THESE:
    "--pssm_threshold", "0.0",  # Allow all amino acids
    "--pssm_multi", "0.0",      # No bias
]
```

## Validation Metrics

### Sequence Quality Metrics

1. **Amino Acid Composition**
   - Should match natural protein statistics
   - No single amino acid > 20% (except in special cases)
   - Hydrophobic/hydrophilic balance

2. **Repetition Analysis**
   - Max consecutive identical residues < 5
   - No long homopolymeric runs

3. **Sequence Complexity**
   - Shannon entropy > 2.5 bits
   - Low-complexity regions < 20%

### Backbone Quality Metrics

1. **Ramachandran Plot**
   - >90% in favored regions
   - <1% in disallowed regions

2. **Clash Detection**
   - No severe clashes (< 0.4 Å overlap)
   - Minimal clashes overall

3. **Secondary Structure**
   - Reasonable alpha/beta content
   - No impossible geometries

## Summary

The repetitive sequences are caused by:
1. **Too low temperature (0.1)** - PRIMARY ISSUE
2. **Insufficient training (5 epochs)** - MAJOR ISSUE
3. **Poor backbone quality** - CONSEQUENCE OF #2

**Quick fix:** Increase temperature to 0.3
**Proper fix:** Retrain with 100 epochs, LR=5e-5, and 100 sampling steps

This should resolve the repetitive sequence problem and produce realistic, diverse protein sequences.
